02What changed: rows became attributable

The Live Feed is per day, not per session, so two agents write into one list. It recorded a four character session id and nothing else, which says the rows came from different tabs but never which tool produced them.

Three ways the field gets set, in resolution order: explicit argument, then DAILY_NOTE_AGENT, then empty. Empty is not an error. A solo feed renders exactly as it did before, so nothing got noisier on single-agent days.

The bug that nearly shipped

Labels were first computed from non-empty values only. That is the obvious implementation and it is wrong, because the realistic rollout state is one runtime emitting the field while another has not adopted it yet. In that state the set of agents has size one, so the renderer concluded there was nothing to disambiguate and printed no labels at all. Every unit test still passed, because each side was correct on its own.

04The licence boundary, in 3D

Drag to orbit. This is the architecture the open-source plan needs, and it is not the one described in the brief. The gap in the middle is the whole legal argument.

drag to orbit · scroll to zoom

Left cluster, MIT

SimpleAgentOS. Must run standalone with zero NovaSystem required. That standalone property is the only thing that makes MIT mean anything to a user.

The gap, MCP

A published general purpose protocol with a defined schema. Particles cross it, but no symbol does. Nothing imports across this line.

Right cluster, GPL-3.0

NovaSystem. Optional and swappable. Plugging it in is how a user knowingly opts into copyleft, rather than inheriting it by surprise.

05What changed: the plan was stated backwards

You described SimpleAgentOS as "a layer I want to put onto the NovaSystem harness". That direction kills the MIT promise. Your intent is right and the sentence is not.

The right hand side is not aspirational. novasystem/memory/journal.py already reaches SimpleAgentOS over plain HTTP and its own commit message states the reason: "SimpleAgentOS owns the PocketBase instance and the schema; this speaks plain HTTP to the same collection and never imports it. Either project runs fine without the other."

What the FSF actually says about the gap

Pipes and sockets normally mean separate programs. But the FSF is explicit that mechanism alone does not decide it: "if the semantics of the communication are intimate enough, exchanging complex internal data structures, that too could be a basis to consider the two parts as combined into a larger program." MCP is a strong fact pattern because it is a published, general purpose protocol with a defined schema that unrelated programs use. It gets weaker the moment the tools start shuttling NovaSystem's internal Python objects across. Keep the wire format a real interface.

07Next steps

Ranked by what breaks trust and what blocks the book, not by what is quickest.

1Put an MIT LICENSE on SimpleAgentOS
Situation
The repo is public and the GitHub licence endpoint returns 404. No licence means all rights reserved.
Why it matters
The entire open-source plan rests on people being able to take SimpleAgentOS freely. Right now, legally, they cannot. Anyone who already forked it has no grant.
Recommendation
Add LICENSE with the MIT text and your copyright line, and declare it in pyproject metadata so tooling sees it too.
Expected outcome
The API returns MIT, the GitHub sidebar shows it, and the promise you want to make becomes real.
Blocked on
Nothing. Two minutes, say the word.
2Decide the dependency direction before writing any MCP server
Situation
You described SimpleAgentOS as a layer on the NovaSystem harness. Measured today, neither imports the other.
Why it matters
If the MIT layer requires the GPL core, the combination is a derivative work and the MIT label stops protecting users. The swappability is not a feature here, it is the legal mechanism.
Recommendation
State it as: SimpleAgentOS runs standalone, NovaSystem is one optional backend behind MCP. Then write the MCP servers to that contract, with a real schema rather than serialised internals.
Expected outcome
MIT means what you want it to mean, and plugging in NovaSystem becomes a deliberate opt-in to copyleft.
Blocked on
You. This is an architecture call, not a refactor.
3Settle contributions before opening the gates
Situation
You own both copyrights, so code can move between MIT and GPL freely today. novasystem.coworking is GPL and is the daily note system generalised, so the two already share design DNA.
Why it matters
The first outside pull request you merge ends that freedom permanently. Relicensing later needs every contributor's agreement.
Recommendation
Either adopt a CLA, or commit publicly to a hard rule that code never crosses the licence boundary. Worth twenty minutes with an actual lawyer given this ships attached to a paid product.
Expected outcome
You keep the ability to restructure, or you knowingly trade it away instead of losing it by accident.
Blocked on
You, and ideally counsel.
